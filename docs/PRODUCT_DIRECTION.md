# AiStu 产品方向

> 状态：已接受的长期方向
> 最近复核：2026-07-27
> 本文回答：为什么做、产品最终成为什么。当前交付边界见
> [`CURRENT_SCOPE.md`](CURRENT_SCOPE.md)。

## 1. 一句话定位

AiStu 是由 AI 深度参与教学过程的桌面学习环境：它诊断学习者具体卡在哪里，
选择可靠知识、合适解释与互动课件，让学习者做出预测或操作，再根据学习证据继续
教学。

它不是教材外面套一个聊天框，也不是让 AI 自由生成页面的低代码平台。

## 2. 要解决的问题

普通教材、题库和聊天式 AI 往往把“内容正确”误当成“已经学会”：

- 正确知识与学习者当下的困惑之间缺少教学编排；
- 长篇解释看似完整，却不能暴露具体误解；
- 抽象结构和执行过程只靠文字难以形成稳定心智模型；
- 用户的预测、错误与重试很少成为后续教学依据；
- 内容、检索索引、社区投稿和个人状态容易混成不可审查的数据层；
- 不同会话之间缺少连续但克制的学习上下文。

AiStu 的核心价值是把一次问答变成可诊断、可操作、可验证、可延续的教学过程。

## 3. 核心教学闭环

```text
用户提出困惑
→ AI 判断问题与可能知识点
→ 用具体例子进行低压力诊断
→ 读取可靠知识与必要前置
→ 选择解释方式和已注册课件
→ 用户预测、排序、选择或操作
→ 根据学习证据纠正误解
→ 记录结构化学习事件
→ 继续教学或安排后续复习
```

以下流程不构成完整教学闭环：

```text
用户提问 → AI 输出长文 → 用户点击“懂了”
```

“看过”“表示懂了”和“能独立解释或迁移”是不同证据等级。

## 4. 产品原则

### 4.1 AI 调整呈现，不改写知识事实

标准知识保存稳定、可审查的定义、关系和基础解释。AI 可以调整顺序、深度、类比、
前置补充、理解检测与课件选择，但不能根据用户状态修改标准定义。

知识事实型回答优先基于本轮检索到的标准知识，并提供可追溯来源。没有可靠匹配时，
可以继续一般性讲解，但必须明确降级，不伪造 `concept_id`、chunk 或出处。

### 4.2 可视化是教学资源，不是装饰

可视化优先服务状态变化、算法执行、结构布局、流程、对比和数学关系。产品不为每个
知识点机械生成页面，也不执行 AI 临时编写的 React、JavaScript、HTML 或 CSS。

运行模型是：

```text
已审核 React 课件
+ 经过校验的场景数据或受限补丁
= 当前教学场景
```

AI 提议新课件时，先在对话中显示建议；用户明确确认后才打开。任意时刻只存在一个
活动课件，新请求更新或替换当前页面。完整决策见
[ADR-0001](decisions/0001-single-active-visualization.md) 与
[ADR-0002](decisions/0002-ai-output-as-untrusted-data.md)。

### 4.3 掌握判断必须基于证据

打开页面或点击“懂了”不能直接判定掌握。更可靠的证据包括：

- 正确预测下一状态；
- 排列正确流程；
- 解释核心机制；
- 在课件中完成关键操作；
- 解决关联或迁移问题；
- 延迟后仍能正确回答。

当前产品可以记录结构化事件，但在证据和模型成熟前不夸大为完整掌握度。

### 4.4 知识、社区、用户与会话状态分离

标准知识不保存用户掌握度、偏好、目标、错题或复习时间。社区投稿保留来源、版本和
审核状态，即使审核通过也不会自动升级为权威知识。用户学习状态只通过稳定 ID 引用
知识对象。

详细决策见 [ADR-0003](decisions/0003-domain-data-separation.md)。

### 4.5 目录是树，知识关系是图

课程目录用于导航：

```text
课程 → 章节 → 小节 → 知识点
```

前置、推导、包含、易混淆和一般关联另行构成知识图。不得为了视觉对称或页面效果
制造不存在的关系。

### 4.6 不固定学习风格标签

产品可以保存可修改的表达偏好，例如简洁或详细、是否优先类比、是否展示公式，
但不把用户永久归类为“视觉型”“听觉型”等固定学习类型。

### 4.7 专项学习是会话范围

学习者可以明确启动某门课程的专项会话。专项范围约束本次检索、Tutor 编排和可选
课件，不写入标准知识，也不自动推断掌握状态。范围外问题需要说明边界并引导用户
退出专项，不能悄悄扩大课程范围。

首次进入专项时只收集轻量、定性的讲解起点。教学从具体例子开始，小题出现在自然
检查点，允许跳过；用户表示看不懂时应立即缩小例子、减少术语，当轮不继续追问。
学习者表示“不会”或首次接触概念时，Tutor 默认先用忠实的日常类比建立直觉，再
明确类比对象与真实概念的对应关系。后续通过少量、可直接点击的引导选项逐步推进，
自由输入作为补充入口，而不是继续学习的必要条件。

每门专项维护独立的本地学习足迹。只有学习者真实发起学习后才记录专项参与；有效
时长只在应用处于前台且学习者近期仍有活动时累计。有来源的讲解记录已接触模块与
知识点，课件完成和预测结果记录为练习证据。课程页与专项会话展示同一份记录。
预测错题与对话误解同样作为练习证据收录进错题本，学习者可随时开启带错题上下文
的复盘会话；复盘状态只表达回顾参与，不代表掌握判定。

成就由上述可验证事件按明确阈值触发，不得因为打开课程、浏览页面或主观起步自评而
点亮。学习时长、内容覆盖和成就表达参与与练习，不自动代表掌握。

### 4.8 商店目录先检索，再明确进入

内容商店首页先展示全国考试一级目录，并允许按考试名称、简称、类别和旗下科目做
本地基础检索。考试卡片负责呈现名称、状态和范围，不把整张卡片作为隐式跳转区域；
用户必须点击卡片右下角明确标注的“进入”按钮，才打开该考试的科目或级别目录。
搜索应提供实时结果数量、清空入口和无结果反馈。

## 5. 内容与能力方向

长期产品能力包括：

- 经过审查的多课程标准知识库；
- 从开放问题发现候选知识点，再加载完整知识对象；
- 根据前置、困惑和目标编排解释顺序；
- 根据具体问题选择定义、类比、流程、对比、做题或纠错等解释方式；
- 经过审查的互动课件与理解检测；
- 学习事件、具体误解、复习任务和延迟检测；
- 可解释的个人知识进展表达；
- 支持多种文件格式、保留来源并经过审核的学习者题库贡献；
- 围绕明确知识点发起的学习讨论，社区观点不冒充标准知识；
- 可复用到更多计算机课程和其他学科的教学运行时。

首期内容方向是计算机专业基础学习。408 数据结构用于验证完整课程与过程课件，
计算机组成原理、操作系统和计算机网络逐步从高价值知识岛扩展。目录中出现一门课程
不等于第一方内容已经完成，产品必须区分“可直接学习”“可添加到课程库”和“建设中”。

## 6. 为什么是桌面端

核心体验需要在一个稳定工作区中同时保留：

- 持续对话与输入草稿；
- 可交互课件；
- AI 对已有课件的结构化调整；
- 课件结果回到教学上下文；
- 本地会话和安全的 Provider 凭据；
- 可控知识快照和离线演示能力。

桌面端不是简单网页封装，而是边界清晰、状态持续的学习工作台。

## 7. 长期非目标

- 只追求更长的聊天答案；
- 把大量未经审查资料当作主要竞争力；
- 用页面浏览或自我声明直接判定掌握；
- 把用户状态写入标准知识；
- 为视觉效果伪造知识关系；
- 让 AI 自由生成并执行不可维护页面；
- 在教学闭环未稳定前扩张庞大插件或社交生态；
- 把社区热度自动等同于知识正确性。

## 8. 长期成功标准

- 学习者能更快定位真正不理解的环节；
- 抽象知识通过预测和操作形成稳定心智模型；
- 事实型回答有可靠来源，未知时会明确降级；
- 后续教学能够使用可解释的学习证据；
- 新课程可以复用知识、Tutor、课件和审查基础设施；
- 产品增加内容规模时仍保持知识事实、社区贡献与用户状态的边界。
