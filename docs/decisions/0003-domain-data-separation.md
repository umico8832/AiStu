# ADR-0003：知识、社区、用户与会话数据分域

- 状态：accepted
- 日期：2026-07-25

## 背景

系统同时处理标准知识、RAG 索引、课件资源、社区投稿、学习者状态和临时对话。
如果这些数据共享一个模型，用户偏好可能污染知识事实，社区热度可能被误当作权威，
页面浏览也可能被错误升级为掌握证据。

不同数据的审核方式、生命周期和可信度不同，需要显式边界。

## 决策

划分以下数据域：

```text
知识内容域
├── authoring 与标准知识对象
├── 真实关系
└── RAG 派生索引

可视化资源域
├── 静态注册表
├── 场景与 patch Schema
└── 课件审核状态

社区内容域
├── 投稿与来源
├── 版本
└── 审核状态

用户学习域
├── 主观起点
├── 学习事件与误解
└── 未来掌握证据与复习任务

会话运行域
├── 消息与草稿
├── 流式状态
├── 专项范围
└── 当前课件 session
```

- 各域通过稳定 `concept_id`、`visualization_id` 等引用协作；
- 标准知识不保存用户状态；
- 社区审核通过不自动进入标准知识库；
- 课件审核不改变知识对象的审核状态；
- 课程自评和页面交互不自动等同于掌握；
- RAG 是知识对象的派生发现层，不替代完整知识对象。

## 后果

优点：

- 可信度与审核责任清晰；
- 社区、个性化和检索可以独立演进；
- 用户数据不会改写共享事实；
- 可以明确解释引用与学习证据。

代价：

- 需要维护跨域稳定 ID 和一致性校验；
- 同一概念可能在多个域有不同生命周期；
- 当前本地 MVP 需要克制地延迟完整用户学习模型。

## 被否决方案

- 在知识对象内增加用户掌握字段：共享事实与个人状态耦合；
- 审核通过的社区内容直接成为权威：缺少独立知识审查；
- 用浏览和点击自动更新掌握度：证据不足；
- 把 RAG chunks 当作权威 authoring：派生数据不可维护。
