# ADR-0001：单一活动可视化与用户确认

- 状态：accepted
- 日期：2026-07-25
- 最近修订：2026-07-25

## 背景

AI 可以为学习问题选择互动课件，但直接打开页面会打断对话，也让模型输出绕过用户
意图。若同时保留多个标签、并排页面或页面栈，对话恢复、焦点、session revision
和课件事件归属都会变复杂。

AiStu 的核心体验是持续对话中的一次教学操作，不是多文档 IDE。

## 决策

- `open_visualization` 只创建对话中的课件建议；
- 用户明确确认后，应用才校验并创建 session；
- 任意时刻只存在一个 `activeSession | null`；
- 同一课件通过受限 patch 更新当前 session；
- 不同课件原子替换当前 session；
- 不实现可视化标签、并排页面、画中画或历史页面栈；
- workspace 位于独立 Electron 窗口中，可切换系统全屏；
- 主对话保持 mounted，课件窗口只通过受校验的领域 IPC 同步当前 session 和事件；
- 关闭后恢复同一会话、草稿和滚动位置。

## 后果

优点：

- 用户始终控制是否进入课件；
- session、revision、焦点和交互事件只有一个明确归属；
- 对话状态无需在多个课件之间同步；
- 学习者可以在全屏课件和持续对话之间使用系统级窗口切换；
- 黄金教学流程更容易测试和演示。

代价：

- 学习者不能同时比较两个互动课件；
- 新课件会替换当前课件的活动状态；
- 独立窗口需要额外维护安全配置、窗口生命周期和受限 IPC；
- 若未来需要对比，必须设计课件内部受控对比视图，而不是放宽全局单实例规则。

## 被否决方案

- AI 命令直接打开：缺少用户确认，模型控制过强；
- 多标签或页面栈：增加状态、焦点、内存和恢复复杂度；
- 对话内浮窗：尺寸受主窗口限制，无法提供系统全屏课件体验。
